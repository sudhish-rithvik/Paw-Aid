## 1. Executive Summary & Migration Sign-Off

The comprehensive backend migration of the PAW AID Android application from **Supabase** and **AWS** to **Firebase Spark** is completed in full.

## 2. AI Integration (LiteRT / TensorFlow Lite Abstraction)

### 2.1. On-Device Architecture
* **Strict Constraint:** Prohibited all hosted AI APIs, Vertex AI, AWS Bedrock, and paid model inference.
* **Service Abstraction:** Created `AnimalTriageService` with a concrete `LocalAnimalTriageService` ([`animal_triage_service.dart`](file:///d:/Projects/Paw-Aid/flutter_app/lib/services/ai/animal_triage_service.dart)) and `AnimalTriageResult` model ([`animal_triage_model.dart`](file:///d:/Projects/Paw-Aid/flutter_app/lib/services/ai/animal_triage_model.dart)).
* **Multi-State UI Support:** The UI in [`ai_report_card.dart`](file:///d:/Projects/Paw-Aid/flutter_app/lib/features/ngo/widgets/ai_report_card.dart) distinguishes between:
  1. `AI pending` (`PENDING`): Active progress indicator while inference runs on device.
  2. `AI completed` (`COMPLETED`): Displays detected species, preliminary urgency, visible injuries, mobility, pain level, confidence score, and recommended responder action.
  3. `AI unavailable` (`UNAVAILABLE`): Clear notification when local `.tflite` model weights are not bundled on the device.

> **"PRELIMINARY EMERGENCY TRIAGE ONLY: This assessment was generated by an on-device automated vision model to assist volunteer dispatch priority. It is NOT a professional veterinary diagnosis."**

## 3. Notification Integration & Spark Plan Security Guardrails

### 3.1. Implementation
* **FCM Service:** [`FirebaseMessagingService`](file:///d:/Projects/Paw-Aid/flutter_app/lib/services/notifications/firebase_messaging_service.dart) initializes user notification permissions via `requestPermission()`, registers a top-level `@pragma('vm:entry-point')` background message handler, and shows foreground alerts via `flutter_local_notifications`.
* **Token Synchronization:** Device tokens are automatically registered to the user's profile document `users/{uid}.fcmToken` in Cloud Firestore and kept current via `onTokenRefresh` stream listeners.
* **Notification Feed:** [`NotificationService`](file:///d:/Projects/Paw-Aid/flutter_app/lib/core/services/notification_service.dart) provides both future and stream queries for the authenticated user.

### 3.2. Architectural Security Constraint
> [!IMPORTANT]
> **Zero Client-Side Notification Broadcasting:** Insecure client-side broadcasting of notifications across devices is strictly avoided. In Cloud Firestore, clients can only write notifications scoped to their own UID. Secure, automated cross-user push notifications (e.g. automatically alerting a citizen when an NGO accepts an assignment) require a trusted backend server or Cloud Functions utilizing the Firebase Admin SDK, which requires Google Cloud Billing (Blaze) and is excluded under the Spark free tier.

## 7. Known Spark Plan Limitations & Future Upgrade Roadmap

The application strictly obeys the constraints of the **Firebase Spark ($0.00 / month)** plan. The following architectural limitations are explicitly documented:

| Feature | Current Spark Implementation | Blaze / Server-Side Upgrade Pathway |
|---|---|---|
| **Distress Photos** | Stored on local device filesystem (`LocalPhotoStorageRepository`). Displayed as "Pending Cloud Storage ($0.00 Spark Mode)". | Integrate Cloud Storage for Firebase (`firebase_storage`) or an S3-compatible free-tier bucket when billing is permitted. |
| **Automated Notifications** | FCM tokens synced to `users/{uid}`. Foreground in-app notifications. | Deploy Cloud Functions for Firebase (`onDocumentCreated('reports/{id}')`) or a secure backend worker to send cross-device FCM alerts. |
| **Initial Admin Setup** | Provisioned manually in Firebase Console or via trusted script (`scripts/provision_admin.dart`). | Implement Firebase Admin SDK CLI or Custom Claims via Identity Platform. |
| **AI Animal Detection** | On-device inference abstraction with local heuristic fallback. | Bundle compiled `.tflite` model in `assets/models/` for full offline neural execution via LiteRT. |
| **Daily Read/Write Quota** | Protected by aggressive 100 MB offline caching and pagination (limit: 20). | Upgrade to Blaze plan for pay-as-you-go capacity beyond 50,000 reads/day. |
